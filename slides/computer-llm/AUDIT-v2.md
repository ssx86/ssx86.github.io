## 🔴 致命认知缺口

### 1. 第 33 页 · "Agent" 术语零铺垫且作为产品分类核心标签反复使用
- **问题**：P33 lede"ZCode / Claude Code 是'专门帮你做东西、能直接动手'的专业 Agent"，底栏"能动手的 Agent"，P34 复用"AI 编程 Agent"。"Agent"作为英文术语首次出现，前面 32 页从未铺垫，且它是 G 段产品分类的核心词（区分豆包vs编程助手的标签），却全程未解释 Agent 是什么、和"助手/程序"什么区别。
- **大脑为何卡住**：截至第 32 页，大脑脑子里只有"豆包=AI助手"和"会聊天AI=大模型=接龙"。它没有任何"Agent"概念，也不知道"Agent"和"助手""程序"的关系。P33 用"专业 Agent"给 ZCode/Claude Code 分类，大脑能抓住"能动手做东西"这个修饰，但"Agent"这个词本身是黑盒——它是一种程序？一种助手？一种大模型？分类标签没听懂，会影响对"这两类产品本质区别"的把握。
- **建议**：
  - 方案 A（推荐，省事）：删掉"Agent"这个词，换大白话。lede 改为"ZCode / Claude Code 是'专门帮你做东西、能直接动手'的 AI 编程助手"，底栏改为"豆包=聊天助手 · ZCode/Claude Code=能动手的编程助手"。全段不用 Agent。
  - 方案 B（保留术语）：P33 首次出现时一句话解释 + 画等号："这种能自己动手干活的 AI，行内叫'Agent（代理）'，你可以理解成'比聊天助手更能干的干活 AI'"。后续再用就不乱。

## 🟠 类比后续失效 / 矛盾

### 1. 第 37/38 页 · "记忆"机制模糊，与 P12"会忘"形成潜在冲突未消解
- **问题**：P11/P12 反复教"它其实不记得""容量有限→会忘"，这是大脑建立的关于大模型记忆的明确认知。但 P37 突然把"记忆"列为四概念之一，说"跨对话把重要信息存下来，下次还能用（是上下文之外的额外能力）"；P38 说"记忆是建立在这条主线上的进阶能力……加了帮手"。记忆是什么机制、谁提供的（大模型自带？还是像技能一样外加的帮手程序？）、和"会忘"怎么调和——从头到尾没讲清。
- **大脑为何卡住**：截至第 36 页，大脑脑子里有明确的"大模型会忘（P12容量有限丢最早）"和"技能=外面套的帮手程序（P35）"。P37 引入"记忆"时，大脑会立刻冲突："前面不是说它不记得、会忘吗？怎么又有记忆了？这个记忆是谁的？是大模型自己记住了，还是又有个帮手？"P38 说"加了帮手"暗示记忆也是外加的，但没明说记忆和技能是不是一类东西。大脑可能形成"大模型又会忘又有记忆"的矛盾感，或把记忆误理解成"大模型自己克服了遗忘"。
- **建议**：
  - 方案 A（推荐，完整）：P37 记忆卡补一句来源说明，明确记忆也是"帮手"性质——"记忆：靠一个帮手程序，把重要信息存下来，下次对话开始时塞回输入——所以它没违反'会忘'，是外面帮它记"。把记忆也纳入"接龙外面套帮手"框架，和技能统一。
  - 方案 B（省事）：如果不想展开记忆机制，P37 记忆卡改为"记忆：有些工具能帮你把重要信息跨对话存下来（具体怎么做到的，和技能类似，是外加的帮手）"，至少点明"外加"不与大模型本身冲突。

## 🔵 推理跳跃过大

### 1. 第 35 页 · 从"预测下一个字"到"接出指令词"中间缺一环
- **问题**：P35 五步流程第2步"接出某个词（比如'去查天气'）"，但 P8 建立的核心模型是"大模型每次只预测下一个字"。从"逐字接龙"到"接出一整句像指令的词（去查天气）"，中间缺解释：模型是怎么从逐字接龙变成接出完整指令的？是它有意决定调用技能，还是无意接出像指令的字串？
- **大脑为何卡住**：截至第 34 页，大脑脑子里的核心模型是"大模型=预测下一个字（一次一个字）"。P35 突然说它"接出某个词（去查天气）"，大脑会困惑：一次一个字，怎么接出一句话？是接了很多个字拼成"去查天气"吗？那它怎么知道要接这四个字？这个"接出指令词"和"预测下个字"的关系没讲清。
- **建议**：P35 第2步补一句过渡——"模型还是一个字一个字地接，但接出的字连起来恰好是'去查天气'这串——就像它接出任何别的话一样，只不过这串恰好被外部程序认作指令"。点明"接出指令词"不违反"逐字接龙"，只是接出的字串被程序识别。

### 2. 第 33 页 · "委托任务，让它自己干"缺具体例子
- **问题**：P33 对比表"怎么用：打字聊天，一问一答 vs 委托任务，让它自己干"。"让它自己干"和豆包"一问一答"的区别，大脑可能模糊——自己干是什么意思？干到什么程度？
- **大脑为何卡住**：截至第 32 页，大脑只见过豆包"打字聊天一问一答"的模式。"委托任务让它自己干"对它是抽象的——自己干是指它能自己操作电脑？能自己读文件？能自己连续做很多步？没有例子，大脑只能想象。
- **建议**：P33 对比表"怎么用"行补一个具体例子——"委托任务，让它自己干（比如'帮我把这堆文件整理成表格'，它会自己读文件、自己写、自己改）"。用一个例子把"自己干"具象化。

## 🟢 术语未解释

### 1. 第 33 页 · "命令行""桌面应用"首次出现未解释（时序倒置）
- **问题**：P33 对比表"住哪：手机 app / 网页 vs 电脑的命令行 / 桌面应用"。"命令行"和"桌面应用"首次出现未解释，而 P34 才解释命令行（"就是那种一串命令的窗口"）。先用后解释，时序倒置。
- **大脑为何卡住**：截至第 32 页，大脑没有"命令行""桌面应用"概念。P33 对比表里这两个词作为"住哪"的答案出现，大脑不知道命令行是什么（"命令的行？什么命令？"），桌面应用勉强能从"桌面"猜是电脑软件。
- **建议**：把 P34 对命令行的解释前移到 P33 首次出现处——P33 对比表"住哪"行改为"电脑的命令行（就是黑底白字敲命令的窗口）/ 桌面应用（像普通软件双击打开）"，首次出现即解释。P34 再展开对比。

### 2. 第 32/34 页 · 公司名集中堆砌（字节跳动 / Anthropic / 智谱 Z.ai）
- **问题**：P32"字节跳动的 AI 助手"、P34"Claude Code 是 Anthropic 出的""ZCode 是智谱 Z.ai 出的"。三个公司专名连续抛给小白，未解释，且不帮助理解产品是什么。
- **大脑为何卡住**：截至第 31 页，大脑脑子里没有任何"公司"概念。这三个公司名对它是纯负担——知道"豆包是字节跳动出的"并不帮助理解豆包能干什么；知道"Claude Code 是 Anthropic 出的"也不帮助理解它是命令行工具。公司名只是"谁出的"，对小白认知产品功能零增益。
- **建议**：
  - 方案 A（推荐）：弱化公司名。P32 删"字节跳动的"，改为"你手机里常用的 AI 助手"；P34 删"Anthropic 出的""智谱 Z.ai 出的"，直接讲产品形态（命令行工具/桌面应用）。公司名对小白无价值。
  - 方案 B（保留）：如果必须提公司，移到底栏或备注小字，不进正文主线。正文只讲产品是什么、怎么用。

### 3. 第 34 页 · "智谱 Z.ai"等号没画 + "图形界面"未解释
- **问题**：P34 lede"ZCode 是智谱 Z.ai 出的桌面应用"，没说明"智谱"和"Z.ai"是同一家公司还是两家，大脑可能以为是两个东西。同页"把命令行包成了图形界面"，"图形界面"首次出现未正式解释（虽可从"像普通软件双击打开"推断）。
- **大脑为何卡住**：截至第 33 页，大脑没见过"智谱""Z.ai""图形界面"。"智谱 Z.ai"并列出现，大脑嘀咕"这是两家公司合作？还是一个公司两个名？"图形界面只能猜。
- **建议**：若保留公司名，写成"智谱（Z.ai）"明确是同一家；"图形界面"首次出现补一句"图形界面就是像普通软件那样有按钮、能点的界面"（其实 lede 已有"像普通软件双击打开"，可把"图形界面"这个词直接删掉，只说"包成了普通软件那样"）。

### 4. 第 37 页 · "提示词"换名未画等号
- **问题**：全篇用"输入""你说的话"指代用户给 AI 的内容，P37 突然用"提示词"这个术语作为四概念之一，没说"提示词就是我们前面说的输入/你说的话"。
- **大脑为何卡住**：截至第 36 页，大脑脑子里"给 AI 的内容"一直叫"输入"。P37 突然冒出"提示词"，大脑会嘀咕"提示词是什么？和我学的输入是一个东西吗？为什么换名字了？"
- **建议**：P37 提示词卡改为"提示词：你给 AI 的话（就是我们前面一直说的'输入'）"，画上等号，后续可混用。

### 5. 第 36 页 · npx 命令 / github 网址 / MIT / 开源 符号术语负担
- **问题**：P36 步骤卡2 显示 `npx skills add https://github.com/lewslulu/html-ppt-skill`，标注"MIT 开源、免费"。对小白，npx（命令名）、github.com（网址平台）、lewislulu（用户名）、MIT（协议名）、开源（概念）全是未解释符号术语。
- **大脑为何卡住**：截至第 35 页，大脑只学过"技能=帮手程序"，没有任何"命令行操作""开源""协议"概念。这条命令字符串对它是天书。虽然讲者说"一条命令就能装"强调简单，但命令本身不可读。
- **建议**：
  - 必做：P36 加一句安抚——"这条命令看不懂没关系，它只是给电脑的一句指令，等下我现场敲给大家看"。降低小白的符号焦虑。
  - 建议：删"MIT"，保留"开源免费"并一句话解释"开源=代码公开，谁都能免费用"。
  - github 网址可保留（大脑知道网址），但不必解释 github 是什么（演示页，看操作即可）。

## ⚪ 轻微 / 可优化

### 1. 第 37 页 · 自检清单少一项（缺"迭代"）
- 七个好对话动作（P20-27）含"⑦迭代追问"，但 P37 自检清单只列六项（角色/背景/标准/例子/格式/拆步骤），缺迭代。建议补"[ ] 迭代追问了吗？"保持七项完整。

### 2. 第 24 页 / 第 18 页 · "对齐"一词偏术语味
- P18 右框"每个信息都对齐"、P24 底栏"例子=最高效的对齐方式"。"对齐"在 AI 圈是核心术语 alignment，这里作为日常动词用虽可懂，但两次出现都偏术语味。建议 P24 底栏改为"例子=最快让 AI 懂你要什么"（与 lede 一致），P18 可保留（日常义更明显）。

### 3. 第 12 页 · 消歧句措辞略绕
- "'容量'不是长短的长度，是能装下多少字"——"长短的长度"语义重复。建议改为"'容量'不是指一句话的长短，是指能同时装下多少字"。

### 4. 第 10 页 · "大模型本质上也是一种程序"略意外
- 大脑有"程序=清单=人写死步骤"（P4-6），P10 说"大模型也是一种程序，只是菜谱不是人写死的"。归类略意外（程序=写死 vs 大模型=续字）。逻辑通顺（P7 已铺垫大模型菜谱非人写死），但"是程序"这个归类对小白略陡。可接受，可在逐字稿补一句"虽然它也属于程序，但它和人写死的程序不一样，它的菜谱是自己学出来的"。

### 5. 第 33 页 · "CloCode"发音纠正略突兀
- 备注"很多人把 Claude Code 听成 CloCode"。小白还没接触过这个词就要纠正发音，略突兀。可保留（无害），或移到 P34 首次详细讲 Claude Code 时。

### 6. 第 35 页 · 五步流程图信息密度偏高
- 五步（接字→接出指令词→识别→替做塞回→接着接）对小白一步到位偏重。建议在逐字稿里分两遍讲：先讲"大模型接字，接出的某些词像指令"（1-2步），停顿，再讲"外面有个程序认出指令，替它做，把结果塞回来"（3-4步），最后"模型接着接"（5步）。图形可保留五步，但讲解节奏拆开。

1. **G-H 段术语管理失控（Agent/命令行/公司名/开源/MIT 集中堆砌）** —— 这是结构性问题而非零散毛病：P32-P36 五页连续抛出 Agent、命令行、桌面应用、图形界面、字节跳动、Anthropic、智谱Z.ai、npx、github、MIT、开源、提示词等十几个未解释术语/专名。第一轮在 A-F 段把术语管理得很好（删自动机/图形界面/few-shot/确定性程序/对齐的锚），但新增的 G-H 段术语管理明显放松，回到了"行话硬塞"的老路。根因是新增内容时没有沿用前面"每个术语首次出现即解释或删掉"的纪律。
