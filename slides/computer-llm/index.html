大家好，今天我会用尽量简单的语言，从"输入"和"输出"这两个最基础的概念出发，带大家理解电脑、程序、以及最近很火的大模型。

第一课 · 电脑

电脑，可以看成一只盒子

它有入口、有出口；中间会发生一些事情

输入 → 处理 → 输出

我们先不要想CPU、内存、硬盘这些名词。把电脑想象成一只盒子：左边有入口，右边有出口。东西从入口进去，在盒子里被加工一下，再从出口出来。这就是输入、处理、输出。

程序就是一份清单。这份清单用电脑能懂的语言写成，告诉它：如果有人输入A，你就做什么；如果有人输入B，你又做什么。清单本身只是文字，只有电脑真正去执行，才会产生结果。

第二课 · 程序

代码是菜谱，运行是炒菜

写过菜谱 ≠ 吃过菜；写好代码 ≠ 已经运行

time.py（代码文件）
# 这是一份代码
import time
now = time.strftime("%H:%M:%S")
print(now)
终端（运行中）
$ python time.py
14:32:05
execute / run = 让代码活起来

代码本身就像菜谱，只是写了步骤。运行（execute/run）就像真正开火炒菜。左边是写在文件里的代码，右边是电脑执行后显示的时间。大家一定要区分：文件是静态的，运行是动态的。

第二课 · 程序

显示时间的程序：没有输入

它只负责输出，人类无法介入控制

无输入 · 只有输出

看一个最简单的程序：显示当前时间。它运行后，只把当前时间打印到屏幕上。这个程序没有输入，人没法跟它互动。你启动它，它输出结果，就结束了。

在图形界面里，输入不一定是键盘。你点按钮、拖滑块、发语音，都是输入。程序收到后，可能更新界面、播放声音、跳出新窗口，这些都是输出。形式变了，但"输入→处理→输出"的本质没变。

第四课 · AI

大模型的雏形：if-else 聊天

输入一句话 → 匹配规则 → 输出下一句话

如果 你说"你好" → 回复"你好呀！"
如果 你说"再见" → 回复"拜拜！"
如果 你说"几点了" → 回复 当前时间
如果 都不匹配 → 回复"我没听懂"
if-else 是规则匹配，不是真理解

现在进入 AI。大模型看起来很神奇，但我们可以从一个最简单的版本开始理解。想象一个聊天程序，里面写满了"如果用户说A，就回复B"的规则。输入一句话，程序匹配规则，输出下一句话。这是大模型的雏形，但它不是真正理解，只是按规则匹配。

大模型一次运行只干一件事：输入一段话，输出一段话

单次运行：输入一段 → 输出一段

大模型的一次运行，本质上和前面讲的程序一样：输入一段文字，输出一段文字。它不会自己主动说，也不会记得你之前说过什么。每次运行都是独立的。

第四课 · AI

第二次运行：输入变了

从第二次开始，输入 = 历史 + 新问题

🧑 第一轮：你好
🤖 第一轮：你好！有什么可以帮你？
🧑 第二轮：（历史）+ 今天北京天气
🤖 第二轮：北京今天晴天。
第二次输入 = 对话历史 + 你的新问题

第二轮看起来大模型记得第一轮，其实不是。第二轮的输入被悄悄改成了"历史 + 新问题"。程序会把前面说过的话一起塞进去，再让模型回答。这样模型才能看起来在延续对话。

第四课 · AI

多轮对话 = 多次运行串联

不是一次超长思考，而是很多次一问一答拼起来的

多次运行 + 累积历史 = 连贯对话

所以真正的多轮对话，不是大模型一次想了很久，而是程序把每次运行拼接起来。每次运行还是一问一答，只是程序把前面所有对话都加到新的输入里。这是大模型能连续聊天的关键。

第四课 · AI

上下文长度是有限的

对话历史太多，盒子装不下，旧内容会被丢掉

上下文有限 → 太久的事会忘记

但是这个装历史的盒子不是无限大的。大模型能同时看到的文字长度有限，叫"上下文长度"。如果聊得太久，最前面的内容会被丢掉，模型就"忘记"了。所以有时候你提到之前的事，它会一脸懵。

第五课 · 概念

四个关键概念

💬 提示词

你给 AI 的"任务说明书"

📜 上下文

当前对话里 AI 能看到的全部内容

🛠️ 技能

让 AI 调用外部工具，比如查天气、算工资

🧠 记忆

把重要信息存起来，跨对话也能用

提示词 · 上下文 · 技能 · 记忆

最后归纳四个概念：提示词就是你发给 AI 的话；上下文是当前 AI 能看到的全部历史；技能是 AI 调用外部工具的能力；记忆是把重要信息存起来，换一轮对话也能用。它们一起让 AI 更好用。
